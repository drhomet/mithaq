# Password links

The starter's auth setup owns delivery policy in `src/mithaq/auth/index.ts`. New projects choose it with `create-mithaq --password-delivery admin|email`, or answer the interactive question. The default is `admin`. Change `passwordDelivery` in the project's `src/mithaq/auth/organizations.ts` later, then rebuild and restart the app.

In administrator mode, a member's action menu issues a one-time password link. The dialog shows its expiry, Copy link, Send by WhatsApp and Cancel link. The starter has no phone field, so WhatsApp asks for a recipient. A project that supplies `member.user.phone` addresses WhatsApp directly. In one-organization mode, Add person offers the same dialog for new staff. Many-organization projects add people by invitation. Administrator and operator links never mark an email address verified. Links expire after 24 hours; issuing a replacement or cancelling spends the previous link. Email delivery retains the existing link and sends no further mail for five minutes. Choosing a password spends every pending link and revokes existing sessions in both hosts.

In email mode, set `RESEND_API_KEY` and `MAIL_FROM` before boot. The mailer uses Resend's HTTP API through `fetch`. A missing key or sender refuses boot. The issue dialog still offers Copy and WhatsApp as a fallback. A forgot-password request mails a link while answering identically for an existing account and an unknown address. In administrator mode the sign-in flow says to ask an administrator, without looking an account up. Password links are never automatically logged, including in development.

An organization issuer needs `member.create` in its verified active organization. The target must belong to that organization alone and carry its creation origin. Adding an existing account invites it; it never gives the inviter control of an existing credential. Owners and super admins alone issue for organization admins, owners or members who manage roles. A super admin may recover shared accounts and accounts created elsewhere. Promotion through governance roles, ERP assignments or custom role permissions cancels pending links. Redemption checks the creation origin and current memberships again, using the same body-or-query token as Better Auth.

The starter stores a creation origin as `password-origin:<user id>` in the provider-only verification table, with the organization id as its value and a year-9999 expiry. Preserve these rows in cleanup jobs. Existing accounts have no origin; a platform operator recovers them through the CLI. Do not infer an origin from a newly attached membership. Projects adopting this feature must merge the starter auth setup, role promotion steps, members component, auth pages, the shared `src/auth-frame.tsx` and `copy.ts` translations; installing a package does not replace project-owned files. No schema or vocabulary migration is required.

For a locked-out administrator, run `node node_modules/mithaq/src/asas/cli/mithaq.ts password-link <email>` from the asas package with `DATABASE_URL` explicitly set. It refuses an unknown address and prints the one-time link once. This server-only operation is unavailable over HTTP. Treat its output as a credential, hand it only to the account owner, and keep it out of logs, issues and screenshots. See the [CLI reference](../../asas/cli/README.md).

Open sign-up with address verification still needs a mailer for address proof and invitations, independently of password delivery. A one-organization project with invitation-only access can run administrator delivery without an email service.
